# everbrew-ui : lessons learned

事後の知見（事象 / 原因 / 対策）。事前の設計判断は書かない。
一般化できるものは **【昇格候補】** を付け、週次の `/知見統合` で中央へ上げる。

## 2026-09-04 #1 A4縦の刷り幅はモバイル分岐に入る 【昇格候補】

- **事象**: 進捗ダッシュボード（型E）を Ctrl+P すると、PC 画面では3カラムのカンバンが1カラムになり、
  ガントの「今日」マーカーが消えた。
- **原因**: A4縦・余白12mm の刷り幅は **186mm ≒ 703 CSS px**。
  `@media (max-width: 768px)` のモバイル分岐に**入ってしまう**。
  「印刷 = 大きい画面」という思い込みが誤りだった。
- **対策**: `@media print` を**モバイル分岐より後ろ**に置き、多カラム配置・フォントサイズ・余白を
  明示的に戻す（同一詳細度なら後勝ち）。`src/status.css` の print 節がその実装。
  印刷CSSを書くときは「印刷 = 狭い幅」を前提にレイアウトを確認する。

## 2026-09-04 #2 `@media print` は「印刷時の分割単位」を節ではなく部品に置く

- **事象**: `.ebs-sec`（節）に `break-inside: avoid` を付けたら、カンバン節の高さ 1040px が
  A4の刷り高 1032px を超え、避けられずに分割された上、前ページに大きな空白が出た。
- **原因**: 1ページに収まらない要素の `break-inside: avoid` はブラウザが無視する。
  節単位で不可分にすると、収まらない節が出た瞬間に破綻する。
- **対策**: 節は分割を許し、**壊れると読めなくなる最小単位**
  （ヘッダー / リング / ガント全体 / カンバンの1列 / ブロッカー1件）だけを不可分にする。
  実測で最大 516px となり、余裕を持って1ページに収まった。

## 2026-09-04 #3 `position: relative` の兄弟は `z-index: auto` の絶対配置を覆う

- **事象**: ガントの「今日」マーカーのラベルが描画されているのに見えなかった
  （`document.elementFromPoint` が `.ebs-gantt__track` を返した）。
- **原因**: マーカー（`position: absolute`）もトラック（`position: relative`）も `z-index: auto` で、
  **DOM順が後のトラックが後から描かれる**。位置指定要素同士は「前に書いた方が下」になる。
- **対策**: マーカー側に `z-index: 1` を付ける。
  目視だけで「消えている」と判断せず、`elementFromPoint` で覆っている要素を特定すると早い。

## 2026-09-04 #4 jsDelivr の `.min` はリポにもワークフローにも存在しない

- **事象**: 「`.github/workflows/build.yml` が `.min` を生成する対象に新ファイルが入るか確認せよ」
  という前提の指示を受けたが、build.yml に `.min` を作る処理は無かった。
- **原因**: `.min` は **jsDelivr が配信時に動的生成**している。リポの `dist/` には存在しない。
  実際 `dist/everbrew-status.min.css` は commit していないのに 200 で配信される（16,819 bytes）。
- **対策**: build.yml は `git add dist` で `dist/` 全体を拾うので、**出力を増やしても workflow の変更は不要**。
  `.min` の健全性はリポではなく **CDN 側で実測**する（minify で `calc()` やカスタムプロパティが
  壊れていないかを、`.min` を読み込んだ実描画で確認した）。

## 2026-09-04 #5 Node の `import.meta.url` はスペース入りパスで壊れる 【昇格候補】

- **事象**: `new URL("./", import.meta.url).pathname` から組んだパスで `ENOENT`。
  実体は `C:\Users\Yuji%20Kenmotsu\...`（`%20` のまま）。
- **原因**: `pathname` は URL のパーセントエンコードを解かない。
  ユーザー名にスペースが入る Windows 環境（`Yuji Kenmotsu`）で必ず踏む。
- **対策**: `import { fileURLToPath } from "node:url"` を使い
  `fileURLToPath(new URL("./", import.meta.url))` にする。
  **`~/.claude/scripts/render-status.mjs`（セッションB）でも同じ罠を踏むので注意。**

## 2026-09-04 #6 承認済みモック HTML は体裁の正本ではない

- **経緯**: Cowork の出力がリポ直下の `Claude outputs/` に落ちていた
  （`status-dashboard-mock.html` / 指示書 `.md`）。プロジェクト規約
  「確認用 HTML は `demo/index.html` 以外に増やさない」に触れるため commit していない。
- **対応**: `..\_scratch\status-dashboard-mock-v2.html` へ移動し、`.gitignore` に
  `Claude outputs/` を追加した（出力先設定が直るまでの保険）。
- **位置づけ**: **見た目の正本は `src/status.css` 冒頭の DOM 契約**。
  モック HTML は「承認時にどう見えていたか」の記録にすぎない。
  モックと CSS が食い違ったら CSS を正とし、モックは更新しない。

## 2026-09-04 #7 IntersectionObserver の reveal は「撮影」で消える 【昇格候補】

- **事象**: viewport 1000px でスクロールせずに fullPage スクショを撮ると、
  下方の節が `opacity:0` のまま写り、2節が丸ごと白紙になった。
- **原因**: reveal を IO だけに任せていた。人が読むときは必ずスクロールするが、
  **スクリーンショット・headless の PDF 生成・印刷プレビューはスクロールしない**。
  `beforeprint` を足しても救えるのは印刷経路だけ。
- **対策**: ①`DOMContentLoaded` から 1500ms のタイムアウトで未 reveal を強制確定
  ②`window.ebsRevealAll()` を公開して自動化から1行で確定できるようにする（冪等）
  ③カウントアップにも中断フラグを持たせ、確定要求後に走行中の rAF が
  中間値を書き戻さないようにする。
  **スクロール前提の演出を入れたら「撮られる経路」を必ず1つ用意する。**

## 2026-09-04 #8 `:first-child` は「見た目の先頭」ではなく DOM の先頭

- **事象**: 「最初のグループ行だけ上余白を消す」ための
  `.ebs-gantt__row--group:first-child` が一度も当たらなかった。
- **原因**: `.ebs-gantt` の実際の最初の子は `position:absolute` の
  `.ebs-gantt__today`。浮いていても DOM 上は先頭なので `:first-child` を奪う。
- **対策**: `.ebs-gantt__today + .ebs-gantt__row--group` を併記する。
  絶対配置の兄弟がある構造で `:first-child` を使うときは、
  DOM 順を実測してから書く（`getComputedStyle` で確認できる）。

## 2026-09-04 #9 `.eb-badge--ok` は AA 未達（未修正・要判断）【昇格候補】

- **事象**: `components.css` の `.eb-badge--ok`（`--eb-ok` on `--eb-ok-soft`）は
  コントラスト **3.80:1**。11px 太字は WCAG の「大きい文字」に当たらないため AA（4.5:1）未達。
  型E の `.ebs-chip--end` が同じ組み合わせで同じ問題を持っていた。
- **原因**: `--eb-ok`(#2f8a57) が soft 面に載せるには明るすぎる。
  既存トークンの組み合わせでは 4.5:1 に届くものが無かった（白 on `--eb-ok` でも 4.29:1）。
- **対策（部分適用）**: `tokens.css` に **`--eb-ok-deep`(#24704a)** を追加した
  （ok-soft 上 5.33:1 / 白上 6.01:1 / surface-2 上 5.61:1）。
  型E の `.ebs-chip--end` はこれに差し替え済み（実測 5.33:1）。
- **未対応**: `.eb-badge--ok` は**あえて変えていない**。
  直すと**既存の全 GAS アプリのバッジの見た目が変わる**ため、影響範囲の判断が別途要る。
  置換自体は `--eb-ok-deep` があるので1行でできる。**人間の判断待ち。**

## 2026-09-04 #10 CSS の16進エスケープは直後の空白を区切り文字として食う 【昇格候補】

- **事象**: `content: "\26A0\FE0E "` と書いた警告アイコンの直後に字間が付かず、
  記号と文字がくっついて出た。空白は書いてあるのに効いていない。
- **原因**: CSS の16進エスケープは最大6桁で、**直後の空白1個をエスケープの終端記号として
  消費する**（`\FE0E ` の空白は「ここでエスケープが終わる」の意味であって空白文字ではない）。
  6桁未満のコードポイントを書いた時点で、区切りの空白は必ず1個食われる。
- **対策**: **字間を `content` の空白に持たせない。** `margin-right` / `gap` など
  ボックス側で持つ。どうしても文字列で持たせるなら空白を2個書くか `\A0`（NBSP）を使う。
  同じ理屈で `\2026x` のように英数字が続く場合も終端が曖昧になるので、
  **エスケープの直後に空白・英数字が来る形は避ける**。

## 2026-09-04 #11 「主数値のサイズを揃える」は数値だけの話。文字列に当てると版面が壊れる

- **事象**: KPI 4枚のうち「現在のフェーズ」だけ値が文字列（"② 進捗ダッシュボード"）で、
  42px（`--ebs-num`）を当てたため 4 行に折り返し **dd 211px**。
  グリッドの stretch で**タイル 4 枚とも 257px**に伸び、KPI 行だけが縦長になった。
- **原因**: `--ebs-num` を「KPI の値の寸法」として定義してしまった。
  実際には**数値のための寸法**で、文字列は対象外。
  モックは全 KPI が数値だったので、実データを入れるまで露見しなかった。
- **対策**: 値の型で分ける。`.ebs-kpi dd.is-text` を DOM 契約に足し、
  文字値は `--eb-fs-5`(19px) に落とす。数値 3 枚の 42px は変えない。
  **「揃える」という指示は同種のものにしか掛からない**ので、
  トークンには「何のための寸法か」をコメントで書く。

## 2026-09-04 #12 件数が伸びる箱に `break-inside: avoid` を付けても守れない 【昇格候補】

- **事象**: 印刷 A4縦(703×1032px)で `.ebs-kb__col`(実装済み 10 件)が **1043px**。
  `break-inside: avoid` を付けているが**紙 1 枚(1032px)より高い**ので約束が守れず、
  ブラウザは無視して途中で切る。
- **原因**: 不可分にした要素の高さが**データ件数に比例して伸びる**。
  モックは各列 2〜3 件だったので露見しなかった。
  `align-items: start`(修正11)で 3 列とも 1043px だったのが最長 1 列だけになり
  露出は 1/3 に減ったが、**最長列そのものは縮まない**。
- **対策(未適用・要判断)**: 不可分の単位を箱ではなく**中身の 1 行**に下げる
  (`.ebs-kb__item` に avoid、`.ebs-kb__col` からは外す)のが筋。
  ただし列ヘッダーと中身が離れるので `break-after: avoid` の併用が要る。
  **一般則: `break-inside: avoid` は「高さに上限がある箱」にだけ付ける。**
  件数で伸びる箱に付けたら、紙の高さを超えた時点で無効になる。

## 2026-09-04 #13 省略記号は「狭い列」の解ではない。折り返しを許して列幅を実測値に合わせる 【昇格候補】

- **事象**: ガント名列に `white-space: nowrap` + `text-overflow: ellipsis` を当てていたため、
  実データ（draft-generator の説明的な6フェーズ名）で**画面 200px で6中5が省略記号**、
  **印刷 116px では全6行が切れた**。
- **原因**: モックのフェーズ名が短く（「実装」「① 樽生・飲み放題」）、
  ellipsis が発火しなかった。ellipsis は「入り切らない時の保険」として書いたが、
  実データでは**常時発火する既定の見た目**になっていた。
  さらに **紙にはホバーが無い**ので、省略記号は復元手段の無い情報の消失そのもの。
- **対策**: `white-space: normal` + `overflow: visible` に変え、列幅を**実測で決める**。
  画面は rail を掃引して実測（160/180/200px = 最大3行 / **220px = 最大2行(33.8px)**）し
  220px を採用。印刷は 180px（最大3行 / 50.6px）。
  **一般則: ellipsis を書く前に、実データの最長値で1回描画する。**
  発火が常態なら ellipsis ではなく列幅か折り返しで解く。

## 2026-09-04 #14 `@media print` の検証は「余白込みの刷り幅」で行う。margin 既定 0 の PDF は無効 【昇格候補】

- **事象**: `page.pdf()` を margin 指定なしで出した PDF は刷り幅 793.7px（＝余白0）になり、
  狭幅由来の破綻（KPI の折り返し・列の溢れ）が**再現しない**。
- **原因**: Playwright の `page.pdf()` は **`margin` の既定値が 0**。
  一方 Chrome の印刷は余白を取るので、本文幅は
  `@page { margin: 12mm }` なら **703px**、Chrome 既定 0.4in なら **716.9px**。
  90px の差が「入る / 入らない」を分ける。
- **対策**: 印刷検証では**必ず margin を明示**する（`page.pdf(format="A4", margin={...12mm})`）。
  ビューポート幅も刷り幅（703 / 717px）に合わせ、`emulate_media(media="print")` を掛ける。
- **併記（Cowork セッションC との不一致・要注意）**: C は「余白0では KPI が折り返さない」
  と報告したが、本セッションの実測は**逆**（703/717px で KPI タイル 98.9px = 折り返し無し、
  794px で 169.8px）。**刷り幅は伝聞で扱わず毎回自分で測る。**

## 2026-09-04 #15 `break-inside: avoid` の単位を箱から中身の1行へ下げると守れる（#12 の対策・実証済み）

- **事象**: #12 の続き。`.ebs-kb__col`（印刷幅で 4068.5px ＝ A4本文 3.94枚分）に
  `break-inside: avoid` を付けていたため約束が守れず、Chromium が任意の位置で切って
  **項目が千切れた**（旧 PDF 実測: i29 のタイトルが p6/p7 に分断、
  i7 の注記「2026-06-22」が p4 に孤立）。
- **対策（適用済み）**: 列は分割を許し、**中身の1件**と**列ヘッダー**だけを守る。
  ```css
  .ebs-kb__col  { break-inside: auto; }
  .ebs-kb__item { break-inside: avoid; }
  .ebs-kb__head { break-after: avoid; }
  ```
- **実測結果**: 同じ11ページで**分断 0 件**（PDF テキスト層で32項目のタイトル前半/後半/注記が
  互いに別ページへ落ちていないことを確認）。1カラム化のフォールバックは**不要だった**
  （9ページに減るが分断は同じ0件なので、情報量を保つ3カラムを維持）。
- **残る潜在リスク**: `.ebs-gantt` と `.ebs-gantt__row` にはまだ avoid が付いている。
  行は最大51px で上限があるが、**`.ebs-gantt` はフェーズ数で伸びる**ので
  フェーズが増えれば #12 と同じ形で破綻する。件数で伸びる箱の一覧として覚えておく。

## 2026-09-04 #16 固定幅グリッド列は「代表値」ではなく DOM 契約が許す最長の形で測る 【昇格候補】

- **事象**: 印刷の `--ebs-span-w: 118px` は **v1.5.0 の時点で全6行の日付が右端で切れていた**
  （必要 124px）。誰も気付いていなかった。さらに修正17 で `__span` に
  `2026-08-27 → （継続）` を許した結果、全角4字ぶん伸びて**必要 139.2px** になった。
- **原因**: 列幅を「だいたいこのくらい」で置き、**DOM 契約が許す文字列の最長形で測っていない**。
  日付だけを想定した幅に、後から全角混じりの書式を足した。
- **対策**: DOM 契約で値の書式を決めたら、**その書式の最長形で幅を実測してから列幅を決める**。
  採用値は 144px（実測 139.2px + 余裕）。
  **余裕を数px 積む理由**: webfont（IBM Plex Mono）が読めない環境では `ui-monospace` に
  フォールバックして字幅が変わる。ぴったりの幅は「フォントが載った時だけ入る」幅。
  なお `text-align: right` の列は溢れても左には流れず**右端で切れる**ので、
  `scrollWidth > clientWidth` を機械的に見ないと気付けない。

## 2026-09-04 #17 `content` の先頭空白は inline-flex では捨てられる（#10 の兄弟）

- **事象**: `.ebs-bl__sev::after { content: " / 受容"; }` が **「LOW/ 受容」**と描画され、
  先頭の空白が消えた。
- **原因**: `.ebs-bl__sev` が `display: inline-flex` なので `::after` が**フレックス項目**になり、
  フレックス項目先頭の空白は捨てられる。
- **対策**: #10 と同じ結論に着地する ― **字間を `content` の文字列に持たせず、
  `margin` / `gap` などボックス側で持つ**（`content: "/ 受容"; margin-left: var(--eb-sp-1);`）。
  併せて**16進エスケープ（`\53D7\5BB9`）も使わない**。桁数が可変で直後の文字を食うし、
  ツール経由で `\` が1個に潰れると `\53` が8進エスケープとして解釈され
  `+D7` のような別文字になる（本セッションで実際に起きた）。
  **CSS の `content` に日本語を出すならリテラルで書く。**

## 2026-09-04 #18 `opacity` で減光した箱の中では、素の色で計算したコントラスト比が成立しない 【昇格候補】

- **事象**: `.ebs-bl__item.is-accepted { opacity: .75 }` の中に
  `color: var(--eb-text-muted)`（白面で **6.75:1**）を置き、コメントに「6.42:1 なので AA 準拠」と
  書いた。実際の合成後は **3.73:1** で **AA 未達**。facts の値も 6.30:1 → 3.63:1 に落ちていた。
- **原因**: `opacity` は**要素と子孫をまとめて1枚のレイヤーにして背景へ合成する**。
  文字色と面色が両方薄まるので、素の色同士で計算した比は残らない。
  「文字は濃いトークンを選んだから大丈夫」という判断が、親の1行の `opacity` で無効化される。
- **対策**: **`opacity` を持つ箱の中の文字は、合成後の値で選ぶ。**
  合成は sRGB 空間の線形補間 `out = a*fg + (1-a)*backdrop` なので、
  背景（この場合 `--eb-surface`）まで含めて計算してから WCAG 比を出す。
  採用: バッジと facts の値を `--eb-text` に上げ、合成後 **7.67:1 / 7.51:1**
  （同じレイヤーのタイトル 7.51:1 と揃う）。
- **一般則**: 減光は `opacity` ではなく**色トークンの選択**で表現するほうが安全。
  `opacity` を使うなら、その箱の中の文字は全部合成後で検算する。
- **未対応（本変更より前から在る同種の問題・週次 /知見統合 へ）**:
  `is-resolved`（`opacity: .55`）の facts 値は **2.48:1**、
  `.ebs-bl__facts dt`（`--eb-text-subtle`・減光なし）は **2.49:1** で、どちらも AA 未達。
  `.eb-badge--ok`（#9）と同じ扱いにする。
